# 支撑断裂即终止（DBL-5 红叉）

在持仓监测的一票否决中，点击「添加支撑断裂终止」，由用户勾选启用。
也可在每次加仓后的卖出条件中单独添加。原有「箱体算法 · K 硬止损」保留，两个条件独立。
默认不启用，不修改账号已有方案、加仓定量或其他退出参数。

新执行版本为 `holding-support-break-v1`，保存在已有箱体条件结构中，原版 `holding-box-stop-v1` 的输出和身份不变。
它读取原生 `darvas_5m_guard_broken`：与图表 `_DBL5_guard_broken` 红叉是同一来源。
上涨期需要一根 5 分钟收盘严格低于防守线；震荡期按用户冻结参数中的连续根数确认。
不把影线触碰、没有有效支撑、箱底短暂被影线穿过当作防守线红叉。
箱体确认、几何窗口、防守冗余和震荡确认根数均可手动设置，保存时冻结参数及版本。
图表与监测须使用相同参数和初始化历史，才能逐点核对；此功能没有修改图表算法或公式。

只处理持仓后确认的红叉，预热历史中的红叉不用于当前退出；缺行情仍报错，不能把缺行情当断裂。
确认红叉后按下一分钟开盘价卖出全部持仓，包含加仓，不假设能成交在已经跌破的旧防守线价。
成交依据保留红叉版本、原生事件名、确认时间和原生 K 线开盘时间。旧版页面不能运行新执行版本，须刷新；旧方案不会自动升级。
阶段条件按同类替换时，新红叉条件与普通箱体触价条件分开归类，不会互相覆盖。
如果加仓 K、动态回撤或其他一票否决更早触发，会先卖出，不会为等红叉推迟已有退出。

# 加仓后动态回撤的口径提示

「动态最大回撤 ≥ 15%」沿用原价格公式，不修改阈值或高点默认值。
设置为「沿用持仓最高价」时，加仓不重置高点；设置为「从本次加仓价重新记录」时，在该次一票阶段生效后重新记录，之后另设阶段也会再次重新记录。
编辑器现在在动态回撤条件旁直接显示此口径、实际生效轮次及保存后须运行新轮次的说明。
已有回放不会因修改设置自动重算。

回归例：持仓最高 420、阶段最高 405，15% 对应价分别为 357 和 344.25。
后续最低 350 时，沿用持仓高点触发，重新记阶段高点尚未触发；后续跌至 340 时阶段规则也触发。
该场景通过真实持仓阶段执行路径验证，包括续算，不需要普通卖出算法同时满足。
