# 动态筛选运行与模板资产保护（567）

## 原始模板兼容读取

`lower-wick-veto`、`veto-history`、`addition-support-quality` 曾直接对否决对象做 JSON.stringify 后哈希。编辑器字段顺序与数据库 JSONB 顺序不同，导致参数未变也被拒绝。

兼容层只重现已知的编辑器顺序和 JSONB 顺序，重新排列字段而不加默认值、不删字段、不改数组顺序；只有完整原参数重现原冻结哈希、且引擎标签一致时才接受。原模板、公式、版本清单、指纹和生效范围保持原样，不写回云端。真正的参数变化仍拒绝使用。

复现样本：长下影线近100根、1 ATR、40%，编辑器指纹 `13ebqeu14l5i7k`，JSONB 顺序指纹 `1t9raau1jelkvk`。回归覆盖参数变化、未知新增字段、数组顺序、历史范围、嵌套急跌窗口与路由分支；不将账号完整模板加入仓库。

## 筛选与存档线程

筛选 Worker 执行原 `collectPreEntryMonitor`，所有行情请求仍由主线程原共享行情加载器处理，保留缓存、限流、初始化与行情边界。公式、原有引擎版本、筛选顺序与最终结果不变。

记录进度使用有确认反馈的单通道增量传递，完整排除记录不丢弃；前次不可变快照保留。取消与线程异常保留最后已确认游标，异常时不回退到主线程继续重计算。

入选库云端备份由 Worker 直接读取原 IndexedDB，再使用原编码、哈希和压缩格式。只传入账号标识及已知内容哈希，避免每次备份先在主线程还原完整大存档再复制给 Worker。原账号校验、远端合并、冲突保护、分块及存档格式保持不变。其他存档适配器继续使用原路径。

动态筛选“命中”只在运行中的进度区域出现，暂停和结束后隐藏，筛选结果仍保留在筛选库。

单元测试和隔离浏览器负载测试不等同于用户账号长时间实盘验收；不得据此承诺任何设备都不会再次崩溃。
