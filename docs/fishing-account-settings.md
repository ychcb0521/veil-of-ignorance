# 捕捞账号参数 v1

在「捕捞 → 算法」中手动编辑后，点击「保存参数」。只有收到云端确认才提示「捕捞参数已保存到账号」。网络失败或 15 秒未确认时提示本机暂存和重试要求。

保存内容：算法卡顺序、启用状态、特征值、统计序列、比较方向、阈值、交集/并集、扫描小时数、向下插针过滤、交易所与重复合约及美股范围、手动/自动模式及间隔。历史扫描截止时间、上次执行时间和本机租约属于运行状态，不纳入账号参数。

整套配置写为独立的 `fish-account-settings.v1` 账号键，复用 `user_sim_state` 的账号隔离与同步机制。旧页面写入旧卡片键不能覆盖新配置。未保存过的账号沿用原有默认值和本机设置；首次点击保存时采用当前编辑值，不按截图替用户填参数。

登录恢复时读取账号配置；已打开页面每 30 秒、切回页面或恢复网络时只核对这个小配置键，不下载研究结果。保存后的卡片优先于旧本机默认值。后台建议计算只展示结果，不再自动覆盖已保存的阈值；手动计算建议仍可用于编辑，下次保存才成为新的固定配置。

前后对比：原来 A 电脑修改算法或阈值只落到本机，B 电脑仍可显示旧参数；现在 A 电脑点击保存并收到确认后，B 电脑登录或重新打开恢复同一整套配置。原指标公式、阈值单位、成交额固定门槛和判定引擎未修改。各电脑的调度执行与本机租约仍独立。

验证覆盖 UI 保存及重开、模拟第二台空白设备恢复、已打开设备接收远端修改、不同账号隔离、云端失败重试、后台建议不覆盖保存阈值及原捕捞/同步回归。自动化中的云端使用替身，未声称完成真实账号的两台电脑人工验收。

验收补充：核心参数和同步相关 101 项通过。扩展 `TimeControl.fish.test.tsx` 复测为 15 项通过、4 项失败；4 项失败都在基线提交 `7ce4c2b8` 复现，涉及信号库/图灵杯文案、旧评分合并和删除确认入口。基线另有时序超时，首次新版运行也出现过列表等待超时；因此不将扩展整面板测试描述为全绿。对照报告保留在本 worktree 的 `work/timecontrol-current.json` 与 `work/timecontrol-baseline.json`，不提交调试目录。
