# 持仓监测：箱体事件与可调 K

实现层：`qualityAdditionStructure.ts` 通过 Deep Dig 的 `evaluateOnBars` 复用 DBL-5 / SBS-5M 的原生状态机，不另写箱体识别。每轮新增可选 `source=structure` 与冻结的结构参数定义；旧规则缺此字段时仍走旧路径。保存身份包括算法版本/原生参数、事件类型、K 基准、冗余单位与数值，参数改变产生新运行身份。

数据以开盘时间输入，只消费 `openTime+5m` 的收盘结果。每笔监测按“入场对齐时刻－该特征预热窗口”固定起点顺序回放，默认至少24h；分页传递完整原生 checkpoint，续算从同一起点重放并按已成交箱体去重。不是截取最后72根重算，也不声称不同初始化起点等价。证据记录实际起点、checksum、原生版本、有效参数和报价规则版本。数据缺失或历史报价精度无效明确失败，不用0或候选价格替代。

DBL抬高事件：UP_STEP / NESTED_HIGHER_FLOOR；确认事件另含BASELINE / SAME_FLOOR，只接受当前被选中的有效主箱体。SBS抬高事件：STEP_CONFIRMED；确认另含BASELINE_CONFIRMED；独立再测试：RETEST_SUCCEEDED，且必须与有效主箱体ID一致。每个箱体最多加仓一次，事件前的数据不能被后续确认回写。额外涨幅门槛按同一收盘价检查，成交按下一分钟开盘。错过事件不会转成持续条件。

K取确认下轨（SBS可选冻结失效价），减用户选定的ATR或百分比冗余；十进制整数运算按实际tick向下取整。只接受0<K<T、开盘仍高于正式下轨，第二次起不降低已有K。原有50%镜像、T-S的ATR门槛、唯一平衡定量及利润一次分配保持。执行、保护性退出、同分钟优先级沿用旧模拟链路。

配置与证据沿用现有账号状态、监测配置库、战役Legs和导出JSON，无数据库模式迁移。未启用或旧配置不自动转入新模式。原生指标、PRS、ATI及其他策略公式不改动。

验证覆盖：DBL/SBS真实状态机确定性样例、未确认/失效排除、事件时间边界、SBS原生失效线、精确冗余与tick、分页/未来追加/续算、每箱去重、涨幅同时门控、风险定量、旧加仓兼容、战役证据与UI逐轮保存。测试使用合成验收行情，不用于声称择时收益改善或参数已拟合。
