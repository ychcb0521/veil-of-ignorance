# 鱼质量：卖出误报标签

每个卖出算法（包括组合、不同阈值水平）的「持仓时间」之后、「卖后反事实」之前增加「卖出误报」。默认折叠成一列，展开后分别显示卖后0.5、1、2、4、6小时的五列。各卖出方案的展开状态独立，也不联动原探测标签、探测值和反事实列。

每个窗口独立使用该次最终卖出价为参考点的反事实数据：

`峰值涨幅 % > 2 × 静态最大回撤2 %` → **卖出误报**。

否则显示「未达误报」，不将其称为准确卖出。等于两倍不标误报，只对机器浮点舍入误差作等值容差；不按显示后的小数判断。回撤为0时直接比较，正涨幅满足，涨幅与回撤均为0不满足。不同窗口的涨幅和回撤不能混用。

仅评估冻结记录证实由本方案普通卖出规则或组合相应阶段触发的最终离场。结构化触发原因优先，止损、短时跌幅、指标一票否决、镜像全部卖出均显示「非算法触发」。半仓镜像后，余仓若最终由原算法触发，仍可评估，从余仓的最终卖出时间和价格开始观察。

历史结果没有结构化快照时，仅普通方案中同时具备引擎明确记录的算法成交原因、有效触发读数且该读数满足冻结规则的记录可以归因。其他旧记录显示「触发原因未知」；不根据当前参数或卖后行情猜测原触发原因。

仍持仓、待卖出、未买入、窗口未满、待补算和缺数据分别显示，不当成「未达误报」。即使缓存标记ready，窗口未完整经过仍不提前判断；缓存必须匹配市场、交易所、标的、最终成交时间、价格及成交分钟处理方式。沿用反事实原规则排除先后不明的盘中成交分钟，只读取已完成窗口。标签不会改变交易成交、收益口径或卖出策略。

折叠摘要的「误报 a/b」只表示b个已能判定的窗口中a个满足条件，下方同时注明已判定窗口数，不是算法总体误报率。合并多次买入时，展开后保留每笔买入的标签和时间，不混合各笔路径。重复探测显示行不会把同一笔卖出重复计算。

展开标签复用现有反事实队列补算、缓存、暂停与重试；仅为标签补算时只请求能归因于算法触发的交易。原反事实展开仍可独立补算所有有效最终卖出。成熟窗口每分钟检查补算，共享请求去重，标签直接随有效缓存更新，不重跑持仓监测。

「鱼质量」「运行结果」导出固定保留五个窗口标签，紧靠反事实读数之前，使用与页面相同的判定。折叠状态随战役页面返回恢复。原使用说明正文不变。
