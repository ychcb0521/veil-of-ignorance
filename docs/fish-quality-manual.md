# 鱼质量使用说明

## 一、目的
用批量挖掘出的信号（鱼）选出四样东西：
- 探测算法及阈值；
- 镜像前卖出算法及阈值；
- 镜像后卖出算法及阈值；
- 两条线的距离 d。

最终标准是几何增长 G，不是总收益或胜率。

## 二、数据准备
1. 批量挖掘：低阈值、多探测算法，尽量多出信号。
2. 去重：
   - 标的 + 信号时间 + 买入时间相同的算一个信号，记下捕获它的全部探测算法；
   - 同一标的、同一探测算法 24 小时内的连续信号算同一波，只留第一个；
   - 汇总给卖出筛选时，同一标的 24 小时内只留最早一个。
3. 路径库：每个信号从买入时间起，存固定窗口 T 内的以下数据：
   - 5 分钟 K 线（开高低收）；
   - 各卖出算法在每个采样点的读数；
   - 各探测算法在入场时的读数。

   路径不受止损、镜像、卖出算法影响，所有回放都在这批路径上做。

## 三、两条线
1. 止损线 = 买入价 × (1 − d)，镜像线 = 买入价 × (1 + d + Δ)。
   - Δ = 4f + s 是成本垫，f 为单边费率，s 为止损滑点；
   - 它保证"镜像卖半仓、剩余半仓打止损"扣成本后正好保本。
2. 名义仓位 ≈ 单笔最大亏损 ÷ d。1R = 打到止损线的亏损。每笔收益扣成本后换算成 R，保本单记 0R。
3. 对每个 d 统计：
   - p(d)：先碰镜像线的单 ÷（先碰镜像线 + 先碰止损线）；两边都没碰到的比例单列；
   - b(d)：镜像触发单的平均 R。基准口径为剩余半仓拿到止损线或窗口到期。
4. 诊断（只作参考，选 d 以 G 为准）：
   - 先涨到 +H 的算好单，统计它到 +H 之前的最大回撤；
   - 先跌到 −H 的算坏单，统计它到 −H 之前的最大涨幅；
   - 画两组分布，看两个密集区是否重叠。
5. 基准：价格为纯随机游走、成本为 0 时，任何 d 下都有 p = 0.5、b = 1、E[R] = 0。
   - p 高出 0.5 的部分归探测算法；
   - b 高出 1 的部分归镜像后的趋势延续和卖出算法。

## 四、卖出算法（镜像前后分开评）
1. 镜像前：负责有限亏损（证伪离场）。看两项：
   - 镜像前离场单的平均 R；
   - 误杀率：被它卖出的单里，若继续持有会先碰镜像线的比例。
2. 镜像后：负责开放盈利。看两项：
   - b；
   - 捕获率 =（剩余半仓卖出价 − 镜像价）÷（镜像后窗口内最高价 − 镜像价），取中位数。
3. 每个卖出算法 × 持仓检测里的各档阈值 × d，都在路径库上回放。组合形式为"镜像前用 A、镜像后用 B"。组合必须整体回放，不能用单项结果推算。
4. 安慰剂对照：把每个信号的卖出读数换成另一个随机信号的读数序列，再回放。真实读数应明显好于安慰剂，否则说明这个算法没读到信息。

## 五、探测算法
1. 先用和卖出无关的标签：在 d 网格上算 p(d)，对照随机入场基线。基线为每个信号配 20 个随机入场：同一标的、信号前后 30 天内的随机时刻。
2. 按入场读数分箱：
   - 默认五分位，每箱至少 30 个信号，不够就合并；
   - 看 p(d) 和 G 是否随读数单调上升，报告 Spearman 系数，G 先用现有卖出配置算；
   - 不单调，阈值就没有意义。
3. 重叠：算探测算法两两之间的信号重叠率（Jaccard），以及各自独有信号的表现。常用算法按独有贡献挑。
4. 和卖出配对：用选出的卖出组合回看探测分层。最优读数区间若移动超过一个分箱，就重选卖出，最多两轮。

## 六、评价与选择
1. G = 各笔 (1 + x·R) 的几何平均，x 为单笔最大亏损占账户的比例。
   - 同时报告 E[R]、按入场时间顺序的最大回撤和最长修复天数；
   - 暂按入场顺序复利，不计同时持仓的资金占用。
2. 比较两个配置只用共同信号，逐笔配对，报告：
   - 好/坏/平计数；
   - 符号检验 p 值；
   - 按日分块 bootstrap 的 95% 置信区间。
3. 选平台不选山峰：按参数 ±1 步邻域的平均 G 排序。
4. 稳健性：去掉对 G 贡献最大的两笔后重算，看结论变不变。
5. 样本外：按信号时间，最早 70% 用于全部筛选，最近 30% 封存。
   - 筛选中不看封存段；
   - 只在最终方案上验一次，报告两段的 G 和衰减。
6. 报告本轮一共试了多少个配置。

## 七、自检（不通过不出结论）
1. 复现：现有参数下，回放结果要逐笔对上"运行结果"里的卖出时间、卖出价、触发原因和收益率。
2. 随机游走：用价格为鞅的模拟路径、成本设 0，只跑止损线、镜像线和窗口到期。应得 p ≈ 0.5、b ≈ 1、E[R] ≈ 0；明显偏离说明有未来函数或计算错误。

## 八、默认参数（可改）
- T = 7 天；
- d = 1%～10%，步长 0.5%；
- f = 0.05%，s = 0.05%（Δ = 0.25%）；
- H = 15%；
- x = 0.1；
- 冷却 24 小时；
- 分箱为五分位、每箱至少 30；
- 随机基线每信号 20 个、±30 天；
- bootstrap 2000 次；
- 样本外为最近 30%。

## 交易战役中的持仓监测

在“交易战役”顶部切换“亲自交易 / 持仓监测”。持仓监测旁的淡色筛选图标默认关闭，点开后可选择卖出方案、探测算法和信号类别，也可查看使用说明与监测统计。已筛选时图标会轻微点亮；关闭窗口保留筛选条件。

战役列表和详情页只显示简洁名称。完整算法条件、阈值和历史说明保存在标题旁的备注入口中；鼠标移到标题或键盘聚焦后可见，点击展开。原始记录、算法及统计口径保持原样。

持仓监测的统计概览仅统计本板块，不混入亲自交易。统计与导出使用「当前筛选 × 操作时间段 × 已选战役」的交集，默认全选。排序行末尾的淡色「… → 批量选择」可勾选卡片、点击散点或选前 N 场；退出选择保留样本，刷新后恢复全选。板块之间各自记住本次选择；筛选或时间段变化不抹掉勾选，仅限制参与统计和导出的范围。清空后概览为空，不会偷偷退回全量统计；「恢复全选」可重新纳入全部当前范围。


## 用 DBL-5 / SBS-5M 设置加仓时机和 K

入口：「渔 → 鱼质量 / 持仓监测 → 条件设置 → 选择监测方案 → 条件加仓」。启用后选择轮次，将「条件算法」设为「箱体支撑 · DBL / SBS」。每一轮分别保存，不会自动替换旧方案的探测 / ATR 设置。

- **DBL-5**：可选“支撑抬高确认”或“新箱体确认（含基准）”。抬高包括完整上移 UP_STEP 和内部箱底抬高 NESTED_HIGHER_FLOOR，二者在依据中区分；普通触底和未选中的新箱体不触发。新箱体确认还包括 BASELINE、SAME_FLOOR。
- **SBS-5M**：可选“支撑抬高确认”“新箱体确认（含基准）”或“独立回踩成功”。前两者使用 STEP_CONFIRMED / BASELINE_CONFIRMED；回踩方式只认正式支撑的 RETEST_SUCCEEDED，不认冻结候选的低点或失败回踩。
- **K 的基准**：默认取已确认下轨；SBS 另可取算法冻结的失效线。两者不同，选择失效线时，额外冗余是在已有失效线之下继续留空间。
- **下方冗余**：默认 0.5 × 已收盘 5m ATR(14)，可改成自定义倍数，也可按基准价格的百分比设置（0 ≤ 百分比 < 100）。0 表示不额外留空间。例：下轨 100、ATR 2、冗余 0.5 ATR，则 K=99；冗余 1% 也得到 K=99。最终 K 按行情元数据的报价步长向下取整，不向上缩窄保护距离。

只在 5 分钟 K 线完整收盘后读结构事件，按紧接该收盘的下一根 1 分钟 K 线开盘价模拟加仓。事件早于半仓镜像成交、入场距离不足、涨幅门槛未过、下一开盘跌至下轨或以下、K 不在有效价格范围，或风险预算无法覆盖时，该事件不成交，也不追认到后面的普通 K 线。等待下一次所选结构事件。同一箱体最多一次；已成交的 K 冻结，后续新一轮 K 不得低于上轮 K。

加仓仍须先完成 50% 初始币数的半仓镜像。保留 T≥S＋本轮入场倍数×ATR 的独立门槛、可选的实际持仓均价涨幅门槛，以及原有平衡定量：`新增币数=[Q×(K−S)+本轮可用落袋利润]/(T−K)`；预算不足不加仓，已使用利润不能重复使用。冗余越大，K 越低，同一事件下通常允许的加仓币数越少，也可能无法覆盖风险。K 触线 / 跳空卖出、卖出优先和同分钟顺序不明时的保护规则沿用原流程。

「监测依据 → 条件与成交明细 → 箱体加仓依据」保留实际事件、下轨、上轨、K 基准、冗余、最终 K、箱体 ID、版本、确认时刻和回放起点。战役及下载中的“箱体加仓依据 JSON”一致。保存后点「开始监测」产生新的结果；旧轮次不改写。这里仍是原有持仓监测的模拟回放，不增加交易所自动下单。
