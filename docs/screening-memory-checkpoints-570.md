# 动态筛选内存与擦除修复（570）

擦除组合表中的动态筛选结果只改变显示标记，不能删除筛选历史或触碰模板。此前擦除把每条记录都变成新对象，首次检查点又把它们全部作为完整变更；保存前的 structuredClone、Worker 消息克隆，以及保存线程整库读取/重写叠加。持续筛选的每次增量保存也会整库读取/重写，计算线程还持有已完成标的的历史。

本版保持筛选计算、版本、参数、读数与完整排除证据不变：

- `veil-pre-entry-monitor-v6/libraries` 不升级数据库版本，不修改旧的 `user:<owner>` / `anonymous` 记录。已打开旧页面仍可使用原格式；旧页面自己的后续写入在新版读取时参与合并。
- 新检查点在同一 store 中写 `incremental:<owner-key>:meta` 与 `incremental:<owner-key>:record:<record-id>`。只读写变化的行，目录与行在同一事务提交。新版读取在单个只读事务中合并原记录、目录和逐条游标，不生成第二份整库 getAll 数组。账号云端备份仍重建完整 version 1 数据，不丢历史；原始模板与公式不迁移。
- `table-clears:<owner-key>` 独立保存记录 ID → 清除时间。擦除只访问这一个小键。它独立通过 `pre-entry-table-clears-v1` 备份，旧页面对原库的写入无法抹掉标记。冻结的组合表筛选快照也按这些标记隐藏，原快照仍保留，供历史入场时间查证。新观测的 updatedAt 大于清除时间后自然显示。
- 首次启动检查点以已读取的 v6 对象为基线，不重新发送已经持久化的历史；实际尚未保存的旧库导入和中断恢复状态仍进入增量。
- 计算 Worker 在主页面确认接收终态结果后释放该标的历史。单分钟各阶段共享同一份不可变读数，数值和证据字段不变。

兼容边界：已加载旧代码的页面继续按其旧界面显示，不能识别新清除标记或新增量键；它不会删除这些独立键。用户自行刷新到新版后才能看到新版保存和清除状态。不要代用户刷新或停止其任务。

重复的原1分钟滞涨独立编辑面板移除。历史方案只在共用区域说明原规则启用状态，并保留显式“另存副本”入口；原字段、指纹、算法源码和执行路径保持不变。
