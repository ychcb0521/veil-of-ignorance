# 动态买前监测

入口位于鱼质量研究的“买前过滤”模块。勾选当前筛选范围中的组合表记录，设置并启用买前条件，然后开始买前监测。

## 判断与入场

- 每轮冻结选中的原始信号、起点、公式、周期、比较方向和阈值。条件全部首次同时满足时，该标的停止；其他标的继续。
- 沿用静态买前过滤的 `qualityMetricPlan`、`warm + 1` 历史窗口及读数计算，只使用当时已收盘的 K 线。不同周期各取最近已收盘读数，不反转公式或比较方向。
- 按分钟推进；0 小时表示到本轮开始时可用行情末尾。暂停保存下一个未判断的分钟，恢复使用本轮冻结条件。
- 图灵杯起始历史不足时先等预热；整个范围都不足则记录原因。内部缺口、缺失字段或 BTC 依赖不能通过填补、跳过或改公式处理。
- “买前监测”库只允许已满足记录生成入场信号。命中时间成为新的信号时间，保留原始信号 ID、时间和监测轮次；原始信号不修改。
- 在库中选择记录，点击“在组合表中勾选”，再使用现有持仓监测。持仓条件如果需要更长历史或 BTC，仍会明确报告缺数据。

## 存储和兼容

独立 IndexedDB `veil-pre-entry-monitor-v1` 保存轮次、游标、状态、读数和来源。通过现有账号存档协议同步独立 blob `pre-entry-monitor-v1`，按账号隔离，按 ID 合并，防止旧页面保存鱼质量研究时覆盖新库。启动前先保存冻结轮次；保存失败不启动。关闭页面中断的轮次加载后显示已暂停。

新增组合表来源 `pre-entry`，原有来源和算法版本保持不变。图灵杯持仓监测遇到未来预取范围中的缺口时收缩读取范围；如果当前所需 K 线本身缺失，仍然停止。该处理不跳过缺口，也不改变买卖公式。

## 验证

- 首次共同命中、严格比较、已收盘边界、与静态过滤数值一致、预热、缺口、暂停继续、原信号保留及持仓衔接。
- 账号切换隔离、启动前保存失败、条件冻结和组件交互。
- 可选真实行情测试：设置 `TURING_REPLAY_FIXTURE` 为本地连续回放文件路径，运行 `src/lib/__tests__/preEntryTuring.real.test.ts`。该测试只读本地文件，不将行情提交到仓库，也不请求币安。
- 本地浏览器已验证真实 Turing 50 的“开始监测 → 独立库 → 组合表入场 → 持仓结束”及刷新后记录恢复。测试用价格大于零仅用于链路验证，不是交易策略推荐。

扩展回归在生产基线 `7c99ec08` 同样存在 detector defaults、trade readings、mirror、repair 断言失败及组合表复制用例超时；不在本次修改算法或重写这些测试。
