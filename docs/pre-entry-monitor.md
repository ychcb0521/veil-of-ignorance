# 买前过滤：静态过滤与动态筛选

“鱼质量”下的批量挖掘、买前过滤、持仓监测为同级主模块，标题字号、图标尺寸和字重一致。“买前过滤”包含两个同级子模块，统一缩进、较小标题与图标，并有内层竖线表示隶属关系；操作按钮沿用原尺寸：

- **静态过滤**：开始过滤 → 条件设置 → 过滤库。只计算原买入节点的已收盘读数，原计算口径不变。
- **动态筛选**：开始筛选 → 条件设置 → 入选库。入选库只收录满足全部条件的记录；全部过程、未满足、等待和报错另在“筛选记录”查看。独立保存买入方案、确认条件和时长，支持暂停、继续、从头筛选并保留历史。

动态条件与持仓监测共用方案编辑组件：按编号新增、复制、改名、选择指标、变量、比较方向和门槛。每套买入方案须填写门槛，可附加买入确认条件；这些条件必须在同一分钟同时满足。不会自动反转公式或门槛。第一次配置可复制旧静态条件作为起点，保存或运行后两套设置互不影响。

## 判断与入场

新轮次冻结 `pre-entry-conditions-v4`、方案版本、指标快照、信号、时长和游标。与持仓监测共用 `findQualityIntrabarExit` 的分钟盘中复原引擎，按分钟推进正在形成的指标 K 线；区别是动态筛选要求买入算法与启用的确认条件全部满足，且没有任何启用的否决触发。标的 × 方案独立执行，首次满足即停在该时刻并记录各条件读数，其他记录继续。

0 小时表示运行至本轮开始时可用行情末尾。暂停继续使用该轮冻结条件；修改条件后从头筛选，旧轮次保留。旧版未标记引擎的轮次继续使用原已收盘算法，`pre-entry-intrabar-v2`、`pre-entry-zero-trade-v3` 轮次保留原规则；已有命中时间不重算。

入选记录保留原始信号 ID、原时间、方案和轮次。命中时间成为新的正式入场时间。在入选库选择记录并点击“在组合表中勾选”，即可由持仓监测调用。图灵杯及入选库使用绝对时间戳，不参与历史捕捞时间迁移。

## 图灵杯专用 v1

在已保存方案旁点“图灵杯副本”，生成独立方案，原方案和结果完整保留。新方案仅用于图灵杯（包括由其生成的入选信号）：

- 以实际首根行情为固定初始化起点，冻结 `turing-origin-v1`，不会合成或补齐此前行情。
- 尚未产生首个有限读数的初始窗口等待初始化；内部 K 线缺口、有效读数之后的缺失仍报错。
- BTC 依赖换为项目已有的独立无 BTC 指标；找不到对应版本时拒绝创建，不擅自替换公式。
- “结构为底·强势进攻”的状态 S 用于组合卖出切换、加仓前提、分支选择，新副本使用 `state-no-btc-v1`。其余阈值、镜像比例、加仓轮次和数量设置沿用所选原方案。
- 结果和版本清单记录初始化版本及首根时间。原版与专用版各有独立结果键，初期读数可能不同。

### 改动前后实例

本地真实 Turing 50 连续行情共 4680 分钟（78 小时），始于北京时间 2026-03-29 13:00。使用内置“结构为底·强势进攻”同系列模板、镜像阈值 2.5% / 卖出 67% 验证（不是用户账号自定义方案的完整快照）：

| 项目 | 原历史口径 | 图灵杯专用 v1 |
| --- | --- | --- |
| 状态 S 预热 | 3074 根 5 分钟，需回看 256 小时 10 分钟 | 从实际首根行情逐步初始化 |
| 13:00 入场所需历史 | 2026-03-18 20:50 起，现有数据不足 | 2026-03-29 13:00 起，不请求虚构历史 |
| BTC 依赖 | 原状态 S 保留 BTC | 使用已有状态 S·无 BTC v1 |
| 实测结果 | 保留完整历史要求，即便单独换无 BTC 仍报历史不足 | 13:00 买入价 125.72，13:16 结束价 122.91，0 次加仓，已完成 |

此外使用“价格 > 0”纯链路条件验证动态筛选：13:01 命中并生成入选记录，后续专用持仓监测使用同一 13:01 入场时间，完成运行且不请求交易所。该例只验证时间与数据链路，不表示策略收益。

原方案仍可出现在组合表中并提示历史不足；应查看新增“图灵杯专用 v1”列的结果。只有专用版才启用新初始化方式。

## 存储兼容

新动态方案及轮次保存在独立 IndexedDB `veil-pre-entry-monitor-v4`、账号 blob `pre-entry-monitor-v4`。读取并合并旧 v1 / v2 / v3 库记录，但不回写旧库，旧页面无法覆盖新轮次或用旧引擎继续新任务。按账号隔离、按记录 ID 合并；存在 v4 设置时优先保留，旧页面后来保存的 v3 设置不能覆盖它；启动前保存冻结轮次，保存失败不运行。

本地行情只读使用，不提交连续回放 JSON、不修改原始数据、不更改 0.01 USDT 换算。构建保留历史静态资源，部署仍须单独确认。

## 零成交等待 v3（版本 528）

仅新开的图灵杯动态筛选使用该规则，持仓监测、真实交易所和原版指标公式不变：

- 行情 K 线必须存在，价格有效，成交量、成交额和主动买入量额明确为 0；缺失字段不视作零。
- 零成交分钟不生成入选节点。依赖成交额 / 成交均价的指标暂时无定义时等待恢复，不把读数填为 0，不沿用旧读数，不修改公式或阈值。
- 因零成交延迟出现的未定义读数（例如 prev(E)）可继续等待；恢复有效之后再次出现无关的未定义读数仍报错。真实 K 线缺口由原取数校验阻止。
- 保存等待次数、首次和最近等待时间；暂停继续重建指标前缀，避免漏判或重复计数。
- 旧轮次不会自动升级。旧轮次失败后可点“保留旧轮次，用新版重新筛选”，或在开始筛选菜单中选“从头重新筛选”。
- 入选库只展示 matched 记录，并且只有这些记录能生成入场信号。其他状态保留在独立筛选记录视图，不能勾入组合表；不删除历史任务数据。

真实 Turing 50 对比：05:30 的分钟 K 线存在，价格 126.56，成交量和成交额均为 0。原 v2 在北京时间 2026-03-30 05:31 报缺失读数；v3 在该时刻等待。以 CDA < 1000 的链路条件从此时开始验证，05:32 恢复有效读数 -4.324226777755635 才入选，生成信号的时间也是 05:32。另以 CDA > 1000 防止提前命中，验证可以继续到原文件第 3538 分钟的真实缺口，并在那里停止。这两个门槛仅用于引擎验证，不是用户账号方案。

v3 验证包括真实回放、暂停恢复、缺字段与真实缺口仍停止、旧版本保留、旧库读取且只写 v3、入选库与筛选记录分离。版本 527 的浏览器验收记录仍属上一版本；本次 v3 的界面交互通过组件测试验证。


## 买前否决 v4（待确认发布）

按本次用户确认，三组条件均用作买前筛选：① 入选算法与确认同分钟全部满足，且 ② 入选前一票否决、③ 卖出条件排除、④ 硬性终止排除没有任何命中时才入选。各组采用持仓监测现有的参数编辑控件与公式；任意否决成立时继续观察，不执行卖出、加仓或模拟持仓。

- 长上影、下插针、高震荡、冲高回落（组合门槛 / 仅 ATR）使用此前已收盘 5 分钟行情与原 ATR 计算。冲高回落峰值从筛选起点起计；“未收复”锁定逐根重建，等完整 5 分钟收盘收复当时峰值。
- 筛选期间急跌使用原 N 分钟完整窗口公式；曾命中则该轮持续否决。静态最大回撤以筛选起点分钟开盘价为基准，动态最大回撤沿用先前峰值到后续低点的计算；最大值不会随反弹清零。
- 1 / 5 分钟跌幅沿用滚动分钟收盘公式，不足 5 分钟从筛选起点起算；跌幅恢复后可入选。
- 指标否决共用原周期的分钟盘中复原。否决指标尚未产生有效读数时等待；真实缺口仍报错。保留 v3 图灵杯零成交等待。
- 箱体 K 使用此前已收盘结构；红叉在该根 5 分钟收盘确认时排除该分钟，不等待模拟成交。原持仓红叉按下一分钟开盘卖出的行为不变。
- 半仓镜像、加仓次数、几何仓位、盈亏比和保本 F 依赖成交持仓，不适用于该模式。相关选项禁用并说明原因，不制造虚构持仓。
- 保存冻结新增参数与版本；复制保留未保存输入，修改时长不重建未改的指标快照。暂停继续从固定起点重建路径，不重复记录已保存的否决次数；静态和持仓配置互不写入。

v4 验证使用隔离测试样本，不代表用户真实账号方案或收益验收。保留旧版验证记录的原版本归属。
