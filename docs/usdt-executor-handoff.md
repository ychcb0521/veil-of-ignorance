# Windows 与 Mac 实盘交接

此版本不需要云服务器。Windows 与 Mac 使用同一套执行代码、各自保管本机凭证，通过指定接收设备的签名交接文件轮流接管同一个账户。API Key、Secret、Windows DPAPI 文件、Mac 钥匙串、网页配对码和设备签名私钥都不进入交接包。请用可信的文件传递方式搬运请求、账本和作废凭据。

当前 Windows 旧执行器尚未升级。开发、打包和模拟验证不代表已经完成真实 Windows → Mac 验收；首次实际切换前需确认安装和停机影响。不要使用原 754 Mac 包启动同一账户。

## 首次准备

1. 两台都安装 Node.js 24.22.2，使用同一交接包。两端运行代码指纹必须完全一致。Mac 通过菜单 1 配置本机代理、同一币安账户和网站账号，凭证只存本机钥匙串；为 Mac 当前代理出口设置币安白名单。
2. 网站需使用含交接监测桥的 755 或后续兼容版本。旧 754 网页没有完整监测快照，旧模板不能靠重新保存来补齐；普通活动战役缺少原监测状态时会拒绝交接。网页配对仍使用各设备自己的本地配对码。
3. Windows 打开新版菜单，传入现有账户目录；首次菜单 1 明确确认后才会停止并禁用旧计划任务，关闭旧重试标记，将任务入口改为新版，同时备份原任务定义及桌面快捷方式。原账本不复制，原凭证目录不搬迁。
4. 旧端停机可能留下未决订单，新版只按原 clientOrderId 查询，查询不到或不完整时禁止继续。接口在首次建立执行权前只读。菜单 2 打开接口（Windows 使用已升级的计划任务后台运行，Mac 保持终端窗口），打开新网页并等待原战役和冻结监测状态同步，再选择 9。账户和账本核对通过才建立原端执行权。

## 每一次交接

1. **新端菜单 4**：生成本机接管请求文件，传到旧端。尚未收到并核对交接账本，新端即使启动接口也不能交易。
2. **旧端菜单 5**：选择请求及一个全新的输出路径。立即持久化冻结状态，禁止开仓、加仓、平仓、撤单、杠杆/保证金变更及后台清理；等待正在处理的操作结束，再只读核对原编号未决委托。失败保持冻结。
3. 旧端在 SQLite 事务内导出逻辑账本，包括普通/托管战役、逐笔成交与费用、原订单编号、手动委托、保护单、杠杆记录、冻结模板、监测检查点、原信号资料及已处理动作。不会直接复制 SQLite 主文件、WAL 或 SHM。完整交出记录持久化后才提供文件；文件写入失败可以向同一请求重新导出同一包，不能换设备再次交出。
4. 交接包生成后，旧端永久停留在“已交出”，重启、定时任务重试、网页恢复按钮都不能重新发交易请求。可关闭旧端接口。Windows 菜单 S 会停止后台任务并关闭重试；Mac 在原窗口按 Ctrl+C。新端**先停止只读接口**，再通过菜单 6 导入，仍不能交易。
5. **新端菜单 7**：重新向币安验证账户和持仓模式，核对所有余仓、普通挂单、条件挂单、保证金模式与杠杆；分页核对原逐笔成交、原订单身份、费用和已实现盈亏。对账期间再次读取仓位和挂单，读数变化或分页不完整就拒绝。未查明操作不能自动作废或换编号补单。
6. **新端菜单 8**：明确选择本端接管，此步骤重新执行完整对账；不会沿用菜单 7 的旧结果。通过后再选择菜单 2 启动。每次进程启动也重新核对；核对失败只提供只读接口。
7. 打开新端配对网页。托管仓位按原检查点继续，普通跟单按原信号 ID、原入场时间、原冻结模板及监测结果继续；历史动作和订单 ID 保留，迁移本身不会创建新战役、重设入场或升级模板。新开仓/加仓仍受原时效约束，已过时动作不会补开。网页必须保持运行，当前版本没有把网页监测引擎迁入常驻后台。

## 失败恢复

- **尚未生成交接包**：原端保持冻结；核对未决订单、网络与监测快照后，可重试导出。若不再交接，菜单 R→4 会重新核对并恢复尚未交出的原端。暂停标志保持原值，不会自动开启原本暂停的跟随。
- **包已生成，新端尚未执行**：新端先关闭只读接口，菜单 R→1 选原包并生成作废凭据。该步骤无需币安网络和 API 鉴权，代理/IP 白名单失败时仍可恢复。作废持久化后该请求和交接包不能再导入。将凭据传回旧端，选择 R→2（接口运行中）或 R→3（接口已停止）接受凭据。旧端仍冻结；如果接口已停止，先用菜单 2 启动只读接口，再通过 R→4 重新对账后恢复。
- **新端已经获准执行**：即使没有实际成交，也不能声称“从未接管”并出具作废凭据。必须完整反向交接最新账本；不能恢复旧备份。
- **交接期间挂单成交、手工交易、仓位/杠杆/保证金设置变化**：新端拒绝启用。尚未接管则用作废凭据退回旧端；旧端按原成交身份重新核对实际变化。无法查明的手动加仓、撤单或保证金操作需先人工核清，不提供跳过对账按钮。
- **交接文件损坏/丢失**：已交出旧端可以为同一接管请求重新导出原包；无原请求不能交给另一端。接管请求、原包、作废凭据和本机数据目录应妥善保留。
- **新端丢失设备身份或无法出具凭据**：旧端不能超时抢回执行权。先在币安撤销/禁用丢失设备的交易权限，再人工核对账户与最新账本并制定恢复方案。不能删除锁、重建空账本或回滚旧库来解除保护。

## 保护边界

签名、接收设备绑定、一次性请求、持久化交出记录及每次发送前的执行权检查，防止遵守本协议的两端并行交易。没有云端仲裁，不能阻止人为复制整个设备目录、恢复旧磁盘镜像、运行不支持交接的旧二进制，或直接使用相同 API 凭证在其他软件下单。不要将本机目录当迁移包复制；需要更强的故障隔离时，应在币安端同步撤销旧设备交易权限。

首次升级备份的旧任务和旧快捷方式不具有交接保护。任何一次交出执行权后，都不能通过恢复旧任务、旧程序或旧磁盘备份重新开启交易。
